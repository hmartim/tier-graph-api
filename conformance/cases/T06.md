# T06 — `unknown` vs. `absent` qualifier

- **Operation under test:** `compareRelationIdentity`
- **Conformance classes:** Core Model
- **Competency questions:** CQ1
- **Executable fixture:** `tier-graph-reference` → `fixtures/cases/T06-unknown-versus-absent`

## Ontological property

`unknown` is **not** `absent`. An unresolved (`unknown`) identity-relevant qualifier blocks
automatic relation merging ([spec/03](../../spec/03-relation-identity.md)).

## Scenario

Two relation candidates agree on source, predicate, target, and polarity, differing only in
the `condition` qualifier: candidate A has `condition = absent`; candidate B has
`condition = unknown`.

## Required invariants

1. Candidates differing only by `absent` vs. `unknown` are **not** equivalent.
2. The decision is `unresolved`, never `equivalent`.
3. `blockingDimensions` names the offending dimension (`condition`).

## Expected behavior

`compareRelationIdentity` returns `decision = unresolved` with
`blockingDimensions = ["condition"]`.
