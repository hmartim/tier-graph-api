# T03 — One evidence unit supporting several relations

- **Operation under test:** `getRelationsByEvidenceUnit`
- **Conformance classes:** Query API
- **Competency questions:** CQ4
- **Executable fixture:** `tier-graph-reference` → `fixtures/cases/T03-one-unit-many-relations`

## Ontological property

Reverse evidence lookup is **complete** and does not conflate distinct relations. One
external evidence unit may support several relations **of distinct predicate families** —
e.g. factual-causal, attributional, and normative-consequential — which MUST remain separate
propositions (the paper's Art. 37(6) decomposition). Collapsing them into one generic edge
would erase the difference between a worldly causal link, an attribution rule, and a legal
consequence.

## Scenario

A single evidence unit `U` is anchored by evidence for three distinct relations whose
predicates belong to different families.

## Required invariants

1. Every relation whose evidence anchors `U` is returned.
2. Distinct relations remain distinct in the result (no merging), including when they share
   endpoints but differ in predicate family.

## Expected behavior

`getRelationsByEvidenceUnit` returns exactly the set of relations linked to `U`.
